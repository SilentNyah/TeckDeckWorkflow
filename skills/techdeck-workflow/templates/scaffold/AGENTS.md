# AGENTS.md

このプロジェクトは `techdeck-workflow` スキルの手順に従う。
手順書の実体はスキル側にあり、このリポジトリには複製しない（二重管理を避けるため）。

* **スキルを扱えるエージェント**: 作業開始前に `techdeck-workflow` スキルを呼び出すこと。
  PPTXの編集・レンダリング・コメント抽出には `pptx-toolkit` スキルを使うこと。
* **スキル非対応のエージェント**: 次を読んでから作業すること。
  `{{SKILL_DIR}}/SKILL.md`
  そこから案内される `workflows/` `reference/` `templates/` を必要に応じて読む。

## プロジェクト固有の情報

| ファイル | 内容 |
| --- | --- |
| `TASK.md` | 目的・対象読者・対象バージョン・範囲・**Current phase** |
| `slides/review_state.md` | スライドごとの進行状態・レビュー履歴（Phase 2 以降） |
| `slides/deck-profile.json` | 配色・フォント・寸法・表記規約 |
| `slides/storyboard.md` | スライドごとの詳細設計（Phase 2 以降） |
| `notes/decisions.md` | 決定の記録（DEC-NNN） |

## 譲れない原則

詳細は SKILL.md §3。ここには特に破られやすいものだけ再掲する。

* エージェント自身の判断でスライドを `APPROVED` にしない。承認はユーザーの明示的な指示のみ。
* エージェント自身の判断で PPTX コメントを `CLOSED` にしない。
* 承認済みスライドを、ユーザーの指示または PowerPoint コメントなしに変更しない。
* **技術的な正確性と説明の十分性を、見栄えや簡潔さより優先する。**
* 内容が1枚に収まらない場合は、説明を削らずスライド分割を提案する。
* 技術的に誤ったフィードバックは、そのまま反映せず、根拠と理由を報告する。
* レビュー用エージェントの判定（`PASS` 等）は承認ではない。承認はユーザーのみ。
* `slides/deck.pptx` は1ファイル。ビルドとレンダリングは直列に行う。
