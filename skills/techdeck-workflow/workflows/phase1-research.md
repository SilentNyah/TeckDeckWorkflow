# `workflows/phase1-research.md`

# Phase 1: 技術情報調査

## Purpose

技術資料に必要な事実、仕組み、前提条件、制約、例外、バージョン差を調査し、Phase 2で構成化できる状態に整理する。

このフェーズではスライド構成やPPTXを作成しない。

## Inputs

作業開始前に次を確認する。

* `TASK.md`
* `sources/source_index.md`
* `notes/findings.md`
* `notes/open_questions.md`
* `notes/glossary.md`
* `notes/visual-references.md`

## Research rules

* 公式仕様、公式ドキュメント、公式ソースコードなどの一次情報を優先する。
* 対象バージョンと適用条件を確認する。
* 一般仕様と特定実装を区別する。
* 正常系だけでなく、制約、例外、失敗条件も確認する。
* 確認できない内容を推測で断定しない。
* 複数の出典が矛盾する場合は、条件やバージョン差を整理する。

## URL handling

ユーザーがURLを入力した場合は、そのリンク先を調査対象として扱う。

1. ページ全体を確認する。
2. 提供元、公開日、更新日、対象バージョンを確認する。
3. 技術的な事実、前提条件、制約、例外を抽出する。
4. 図、表、コードも必要に応じて確認する。
5. 既存の調査結果との一致・矛盾を確認する。
6. Markdownへ追記する。

複数URLがある場合は、個別に調査したあと、共通点、相違点、バージョン差を統合して整理する。

PDFや仕様書の場合は、本文だけでなく目次、図、表、注釈、付録、改訂履歴も確認する。

アクセスできない場合は推測せず、理由を `notes/open_questions.md` に記録する。

## Visual reference research

**テキストと並行して、図・図解・画像も調査対象にする。**

理由は装飾ではない。**どう説明すれば伝わるかは、既に誰かが解いていることが多い。**
公的機関の資料、公式ドキュメント、規格書には、その分野で定着した図の型がある。
それを知らずに一から図を考えると、本文で書けることを本文で書いてしまう
（`reference/visual-design.md` §5 が禁じている状態）。

### 手順

1. テキスト調査で得た一次資料に、**図・表・フローチャートが含まれていないか**を必ず確認する。
   **これが最優先。** 一次資料の図は、出典が明確で、内容も検証済みである。
2. **PDF は本文だけ読んで終わりにしない。** `Read` の `pages` で該当ページを開けば、
   図をそのまま**見る**ことができる。目次・図表一覧から図のあるページを特定する。
3. 一次資料に図が無い場合に限り、解説記事・図解を探す。
   検索語は「<トピック> 図解」「<topic> diagram」「<topic> architecture」など。
4. 候補画像は `sources/images/` に保存し、**実際に開いて見る。**
   URLを記録しただけで見ていないものは、調査していないのと同じである。
5. `notes/visual-references.md` に記録する（`templates/visual-reference-entry.md`）。

### 記録すること ─ 画像そのものではなく「構造の型」

各画像について、**何を上手く表しているか**を言語化する。ここが成果物である。

| 構造の型 | 何に効くか |
| --- | --- |
| 対比（左右2列） | 適法/違法、Before/After、期待/実際 |
| 時系列（横軸） | 手順、ライフサイクル、処理順 |
| 階層（入れ子） | 包含関係、スコープ、レイヤ |
| フロー（矢印） | 制御の流れ、データの流れ、判断分岐 |
| マトリクス（表） | 2軸の場合分け |
| 中心と周辺 | 主役と寄与要因 |

Phase 2・3 は**この型を使って自分で描く。**

### 著作権 ─ 見つけた画像をデッキに貼らない

* **既定は「構造だけ翻案し、自分で描き直す」。** 型に著作権は無いが、図そのものにはある。
* 出典表示があれば貼ってよい、という判断を**エージェントが独断でしない。**
* どうしても現物が必要な場合（公的資料の様式そのものが説明対象である等）は、
  `notes/open_questions.md` に `OQ-NNN` を立て、**ユーザーの判断を仰ぐ。**
* ライセンスが明記されている素材（CC0、パブリックドメイン、官公庁の利用規約で
  複製が明示的に許可されているもの）は、その根拠を `visual-references.md` に記録する。

### アクセスできない場合

推測で「たぶんこういう図」と書かない。理由を `notes/open_questions.md` に記録する。

## Outputs

次を更新する。

* 出典情報: `sources/source_index.md`
* 技術的な結論: `notes/findings.md`
* 未確認事項: `notes/open_questions.md`
* 用語: `notes/glossary.md`
* 視覚参照: `notes/visual-references.md`（画像は `sources/images/`）
* 必要に応じた判断: `notes/decisions.md`

記録形式は次を使用する。

* `templates/source-entry.md`
* `templates/finding-entry.md`
* `templates/visual-reference-entry.md`

必要に応じて検証コードを `examples/` に作成する。

## Completion

完了時は次を報告する。

* 調査した範囲とURL
* 重要な技術的事実
* 対象バージョンと前提条件
* 制約、例外、実装差
* 更新したファイルとSource ID
* **見た図と、そこから採用する構造の型**（`VIS-NNN`）
* 未確認事項（図の利用可否の判断が要るものを含む）
* Phase 2で扱うべき技術項目
* **Phase 2 で図にすべき項目**（本文で書くと長くなるもの）

報告後は停止し、ユーザーの指示なしにPhase 2へ進まない。
